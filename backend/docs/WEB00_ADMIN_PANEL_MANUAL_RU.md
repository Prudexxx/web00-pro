# WEB00 Admin Panel Manual

## Создание Карточки

Откройте раздел `Сайты` и нажмите `Создать черновик`. Карточка создаётся одним
нормальным сохранением: заполните основные данные, демо, каталог, коммерцию и,
если нужно, изображения, затем нажмите `Сохранить карточку`.

Обязательные поля обычного flow:

- `Название сайта`
- `Категория`
- `Короткое описание`

`Адрес карточки` создаётся автоматически из названия. В обычном сценарии его
не нужно менять вручную. Если нужен точный адрес или нужно исправить конфликт,
откройте `Расширенные настройки` и используйте поле `Адрес карточки` или кнопку
`Сгенерировать заново`.

После успешного создания черновика форма показывает следующий шаг:

- `Перейти к изображениям`
- `К списку`

Это защищает от случайного повторного POST после успешного создания.

## Демо

В секции `Демо` есть select `Есть демо?`.

- `Без демо` - используйте, если отдельной рабочей demo-ссылки нет.
- `Внешнее демо` - используйте, если есть внешняя demo-страница.

Для внешнего демо заполняется одно поле: `Ссылка на демо`. Админка сама
раскладывает эту ссылку по внутренним backend-полям.

Технические URL-поля остаются только в `Расширенные настройки`. Они нужны для
редкой точечной правки, а не для обычного создания карточки.

## Коммерция

Цена вводится в рублях в поле `Цена, ₽`. В копейках ничего вводить не нужно.
Админка сама переводит значение в backend-формат.

Примеры допустимого ввода:

- `15000`
- `15 000`
- `15000,50`
- `15000.50`

Если цена указана с минусом, равна нулю, содержит слишком много знаков после
запятой или слишком велика для сохранения, ошибка показывается рядом с полем.

## Изображения

В форме создания есть секция `Изображения — необязательно`.

Можно выбрать:

- `Preview файл`
- `Alt для preview`
- `Gallery файлы`
- `Alt для gallery`

Лимиты: JPG, PNG, WEBP, AVIF; 5 MB на файл; gallery batch до 10 файлов и до
30 MB; всего в gallery максимум 20 изображений.

Если изображения выбраны до нажатия `Сохранить карточку`, админка сначала
создаёт карточку, затем загружает preview/gallery без второго сохранения
карточки. Если изображения не выбраны, create остаётся обычным сохранением
карточки.

После создания черновика можно открыть отдельный экран изображений через
`Перейти к изображениям`. Из списка сайтов экран изображений также доступен
через действие `Изображения` у карточки.

На экране изображений управляются:

- `Preview`
- `Gallery`

Если карточка создана, но часть изображений не загрузилась, UI показывает:

`Карточка сохранена. Часть изображений не загрузилась.`

Кнопка `Повторить загрузку изображений` повторяет только неуспешные изображения
и не повторяет create POST. Для публикации карточке нужен preview; если preview
не добавлен, админка покажет понятную ошибку перед публикацией.

## Редактирование

Из списка сайтов нажмите `Редактировать`. Форма показывает сохранённые данные:

- `Цена, ₽` отображается в рублях.
- `Есть демо?` отображается как select.
- `Ссылка на демо` показывает обычную demo-ссылку.
- `Расширенные настройки` остаются свернутыми по умолчанию.

Editor может редактировать draft-карточки. Admin может управлять более широкими
полями и жизненным циклом карточек.

## Восстановление Формы

Форма автосохраняет черновик введённых полей локально в браузере. Это нужно на
случай перезагрузки страницы, кнопки back, ухода страницы в фон, события
`pagehide`, offline-состояния, нестабильного мобильного интернета или VPN-сбоев.

Если найден локальный черновик, админка показывает:

`Найдены несохранённые данные. Восстановить?`

Доступные действия:

- `Восстановить`
- `Удалить черновик`

После успешного server save локальный черновик очищается. После ошибки
сохранения или истечения авторизации введённые данные остаются доступными.

Локальное восстановление не должно хранить пароли, токены, cookies,
authorization headers или другие secrets.

Локальный draft хранит stable create operation id (`clientRequestId`) для
безопасного повтора той же операции. File/Blob-данные и пути файлов в storage не
попадают. После полного reload текст может восстановиться, но выбранные файлы
нужно выбрать заново; UI показывает:

`Текст восстановлен. Изображения выберите повторно.`

## Network Error

Если сохранение не получило ответ от сервера, форма остаётся на экране. Для
create используется один stable `X-Request-Id`. После `REQUEST_TIMEOUT` или
`NETWORK_ERROR` админка проверяет readiness, делает один безопасный повторный
POST с тем же `X-Request-Id`, затем при необходимости проверяет точный
`Адрес карточки` через список сайтов.

Если запись найдена, сохранение считается успешным и можно перейти к
изображениям. Если запись не найдена, админка показывает:

`Сервер не ответил. Запись не найдена. Можно повторить.`

После такого сообщения можно повторить сохранение вручную.

Если тот же `X-Request-Id` уже использован с другими данными, UI показывает:

`Эта операция уже использована с другими данными. Начните новую карточку или обновите форму.`

Если replay результата невозможен, UI показывает:

`Не удалось восстановить результат предыдущего сохранения. Передайте requestId разработчику.`

## Readiness И Timeout

При открытии админки сначала показывается:

`Backend просыпается, подождите...`

Админка вызывает `/api/ready` без авторизации и только после успешной readiness
проверки запускает auth bootstrap. Если backend не отвечает в пределах общего
deadline, показывается отдельный экран:

- `Backend пока недоступен`
- `Введённые данные не потеряны`
- `Повторить проверку`

Модель timeout:

- обычный JSON GET: 25 секунд;
- JSON mutation: 45 секунд;
- одна readiness attempt: 15 секунд;
- общий readiness budget: 90 секунд;
- multipart upload: 120 секунд.

## RequestId

Если сервер вернул неизвестную ошибку или ошибку без конкретного поля, UI
показывает `requestId`. Его можно скопировать кнопкой `Скопировать requestId`
и передать разработчику для диагностики.

`requestId` не является паролем или токеном, но его всё равно стоит передавать
только внутри рабочей диагностики.

## Публикация

Публиковать может admin. В списке сайтов для draft-карточки доступно действие
`Опубликовать`.

Перед публикацией проверьте:

- карточка сохранена как draft;
- добавлен preview;
- демо-ссылка, цена, описание и изображения выглядят корректно;
- публичный каталог должен получить именно эту карточку.

Если preview отсутствует, UI показывает:

`Перед публикацией добавьте preview-изображение.`

## Снятие С Публикации

Для опубликованной карточки admin может нажать `Снять`. Карточка вернётся в
draft и исчезнет из публичной выдачи после подтверждения сервером.

## Удаление И Восстановление

Для активной карточки admin может нажать `Удалить`. Это soft delete: карточка
скрывается как удалённая, но её можно найти фильтром `Только удалённые` и
восстановить.

Для удалённой карточки доступны:

- `Восстановить`
- `Удалить навсегда`

`Удалить навсегда` нельзя отменить. Для permanent delete UI требует typed
confirmation. Владелец должен применять permanent delete только к тестовой
карточке и только после отдельного подтверждения.

## Ограничения Ролей

Editor:

- может создавать и редактировать draft-карточки;
- может управлять изображениями draft-карточек;
- не публикует и не выполняет destructive lifecycle actions.

Admin:

- может редактировать расширенные поля;
- может управлять изображениями draft/published карточек;
- может публиковать, снимать с публикации, удалять, восстанавливать и выполнять
  permanent delete при наличии подтверждения.

## Что Нельзя Делать В Админке Без Approval

- менять, публиковать или удалять live-карточки, если задача этого не требует;
- публиковать тестовую карточку без отдельного owner approval;
- выполнять permanent delete для не-тестовых карточек;
- передавать пароли, токены, cookies или secrets в отчёты и комментарии.
