# WEB00 Open Questions

Дата: 2026-07-03  
Назначение: серые зоны и решения по умолчанию для WEB00 Pro 2.0.

## 1. Главная цена: Start/Business/Pro или low-tier?

Решение по умолчанию:

```text
Start / Business / Pro = premium main pricing.
```

Текущий canon:

- Start — от 39 000 ₽
- Business — от 69 000 ₽
- Pro — от 99 000 ₽

Low-tier цены `7/12/15/3/500` не использовать как главную pricing-сетку. Их можно позже оформить как минимальные услуги, доработки или add-ons.

Статус: принято как default, требует финального бизнес-подтверждения.

## 2. Нужен ли account до backend?

Решение:

```text
frontend shell yes, real auth later.
```

Можно готовить внешний вид кабинета, но нельзя обещать реальный личный кабинет с авторизацией до backend.

Статус: принято.

## 3. Нужно ли сравнение сайтов?

Решение:

```text
да, should-have после стабилизации каталога.
```

Сравнение должно помогать выбрать 2-3 сайта, а не превращать каталог в шумный marketplace.

Статус: should-have.

## 4. Нужен ли подбор сайта?

Решение:

```text
да, should-have.
```

Подбор нужен для клиентов, которые не понимают, какой сайт выбрать. Первый вариант может быть простым decision flow без AI.

Статус: should-have.

## 5. Нужен ли QR в hero?

Решение:

```text
нет.
```

QR показывать только после возникновения ценности:

- после заявки;
- в статусе;
- в кабинете;
- в контактах;
- на install page.

Статус: принято.

## 6. Нужен ли APK?

Решение:

```text
нет, сначала PWA.
```

APK/RuStore не делать до проверки PWA, backend и реальной потребности.

Статус: принято.

## 7. Где кнопка ошибки?

Решение:

```text
footer/status/cabinet/help, не главная CTA.
```

Bug report не должен выглядеть как основной публичный action и не должен конкурировать с запуском сайта.

Статус: принято.

## 8. Нужно ли показывать SEO/Performance словами?

Решение:

```text
нет, только человеческими формулировками.
```

Публично:

- Быстро загружается
- Готов к продвижению
- Удобен на телефоне
- Проверен перед запуском

Внутри можно хранить технические метрики.

Статус: принято.

## 9. Можно ли запускать backend сейчас?

Решение:

```text
нет, после frontend contract.
```

Сначала:

- frontend canon;
- screen flow;
- component inventory;
- API/data contract;
- clean state.

Статус: принято.

## 10. Можно ли запускать QAMax сейчас?

Решение:

```text
нет, после clean frontend/backend.
```

QAMax сейчас даст много шума. Запускать после стабилизации frontend foundation и основных сценариев.

Статус: принято.

## 11. `solutions.html` или `catalog.html`?

Решение по умолчанию:

```text
сейчас оставить solutions.html, позже можно добавить catalog.html alias/rename strategy.
```

Причина: текущий проект уже завязан на `solutions.html`, резкое переименование может сломать nav, sitemap и внешние ссылки.

Статус: открыто для отдельной migration wave.

## 12. Что делать с `landings/*` и `demos/*`?

Решение по умолчанию:

```text
не удалять сейчас, классифицировать.
```

Возможные роли:

- demos для iframe preview;
- legacy examples;
- будущие шаблоны;
- мусор после миграции.

Статус: открыто.

## 13. Что делать с `home-1to1-test.css`?

Решение по умолчанию:

```text
не отключать сейчас, но переименовать/очистить в CSS cleanup wave.
```

Он фактически рисует текущую главную, но имя `test` не подходит production.

Статус: открыто до cleanup.
